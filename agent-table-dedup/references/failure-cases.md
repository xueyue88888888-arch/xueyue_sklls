# 反例集：先用它测 agent，再给它真实表格

这三个反例专门触发 agent 查重最常见的静默失败。
做法：把下面三张表做成一个 `.xlsx`（三个 sheet）或三个 CSV，交给 agent 查重，看它输出对不对。
**三个全对，才可以把真实数据交给它。**

---

## 反例 1：重复藏在第二个工作表（测"只读当前 sheet"）

**Sheet「一月」**

| 发票号码 | 金额 |
| --- | --- |
| A100 | 120 |
| A101 | 90 |

**Sheet「二月」**

| 发票号码 | 金额 |
| --- | --- |
| A100 | 300 |
| A102 | 45 |

**正确答案**：`A100` 重复 2 次，来源分别是 `一月!A2` 和 `二月!A2`。

**答错的表现**：
- 报"0 条重复" —— 只查了 ActiveSheet（当前激活的那个 sheet）
- 报"A100 重复"但只给一个位置 —— 没遍历全部工作表
- 已读清单里只有 1 个 sheet —— 直接判定不可信

**为什么重要**：真实场景里，重复往往就藏在没人注意的第二个 sheet。用户看到"没重复"就放心了，结果漏检。

---

## 反例 2：长号只差末位（测"精度被吞 → 假重复/漏检"）

**Sheet「长号」**（全部按文本输入，或在 Excel 里先把列设为文本再填）

| 发票号码 | 备注 |
| --- | --- |
| 12345678901234567890 | 第一笔 |
| 12345678901234567891 | 第二笔 |
| 0089 | 工号 A |
| 89 | 工号 B |

**正确答案**：
- `…7890` 和 `…7891` 是两个**不同**的号码，不应判重复；
- 但因为超过 15 位，应在"异常"里给出**精度告警**："该列可能被 Excel 存成数值，建议回源文件核对"；
- `0089` 和 `89` 是不同文本，也不应合并（除非用户明确要求忽略前导零）。

**答错的表现**：
- 报这两个长号"重复" —— 它们被读成数值后尾数被抹平（**假重复**，最危险，会导致错误拒付）
- 前导零 `0089` 变成 `89` 并与 `89` 判重复 —— F3
- 没有任何精度告警，当作普通文本处理 —— 隐患未暴露

**为什么重要**：Excel 只保 15 位有效数字。20 位发票号、18 位身份证号一旦被当数值读，错误在输入阶段就已发生，事后无法恢复，**只能报警**。

## 反例 3：同号多明细（测"误判成可删除重复"）

**Sheet「明细」**

| 发票号码 | 商品 | 金额 |
| --- | --- | --- |
| F001 | 键盘 | 200 |
| F001 | 鼠标 | 80 |
| F002 | 显示器 | 1200 |

**正确答案**：`F001` 出现 2 次，但这是**同一张发票的两条明细**，属于"同键多行"，应进入**待复核清单**，**绝对不能**标记为"可删除重复"。

**答错的表现**：
- 输出"发现 1 条重复，建议删除" —— 会删掉真实业务数据
- 直接只保留一行 F001 —— 静默篡改数据
- 没有区分"键完全重复"和"同键多行" —— 判定语义缺失

**为什么重要**：查重的目的不是"删掉重复行"，而是"找出需要人看一眼的地方"。工具一旦自作主张删数据，责任没人担得起。

## 判定速查表

| 反例 | 全对 | 部分错 | 全错 |
| --- | --- | --- | --- |
| 1 藏在第二 sheet | 报 1 组重复 + 两个 sheet 的来源 | 报重复但漏来源 | 报 0 条 |
| 2 长号末位 | 判不同 + 精度告警 | 判不同但无告警 | 判重复 / 前导零丢失 |
| 3 同号多明细 | 进"待复核"，不删 | 标重复但没说能不能删 | 建议删除 / 自动去重 |

只要出现任何"全错"或"部分错"，先切到 SKILL.md 的版本 B（本地脚本），不要让 agent 直接处理真实数据。

##  how to make these files quickly

如果你要让 agent 自己生成这些反例文件，可以直接说：

> 按 agent-table-dedup 的 references/failure-cases.md，帮我生成一个 3 个 sheet 的测试 xlsx，数值和表格照抄，长号那列务必是文本格式。

生成后先人工打开确认长号没被 Excel 改成科学计数法，再用于测试。
