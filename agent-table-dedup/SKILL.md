# Agent 表格查重：让 AI 查得对，而不是查得快

## 谁用、解决什么

有人手里一堆 Excel/CSV，想按某一列（发票号、订单号、工号、身份证号）查重复。
第一反应是丢给 agent：「帮我看看这几个表有没有重复」。agent 确实能做——**但默认做法经常静默出错**，而且错了不报错。

这个技能不写一个查重工具。它做三件事：

1. 给一段**可直接复制的查重提示词**，让 agent 按正确流程做；
2. 给一份**校验清单**，防止五类静默失败；
3. 给一组**反例文件**，让你在相信结果之前先测 agent 会不会翻车。

> 核心判断：**能被 agent 一句话替掉的工具不该做。该做的是让 agent 别把这件小事做错。**

## 什么时候用 / 什么时候不用

| 场景 | 用不用这个技能 |
| --- | --- |
| 一次性自己看看，重复了就删 | 不用。直接让 agent 查就行 |
| 结果要交审计、发客户、上报，错了要担责 | **用**。按本技能加校验 |
| 数据敏感、不能上传公网 | **用**。本技能强制本地/脱敏流程 |
| 号码是 20 位发票号、带前导零的工号/身份证 | **用**。这是最容易静默出错的地方 |
| 只是两列文本去重 | 不用，杀鸡用牛刀 |

---

## 五类静默失败（这是技能存在的理由）

agent 查重不是"能不能"，是"错了你知不知道"。按危险程度从高到低：

| # | 失败 | 为什么危险 | 反例信号 |
| --- | --- | --- | --- |
| F1 | **只读当前工作表 / 提前退出** | 报告"0 条重复"，其实少读了一个 sheet 或遇到第一个重复就 `Exit For`。用户无从自证 | 结果里没有"已读哪些文件/表/多少行" |
| F2 | **20 位号码精度被吞** | Excel 只保 15 位有效数字。两个不同的号可能被读成同一个 → **假重复**（错误拒付），或尾数丢失 → **漏检** | 结果里该列是数字类型；没有超 15 位告警 |
| F3 | **前导零丢失** | `0089` 被读成 `89`，`0089` 和 `89` 被当成同一个 | 键列被自动转成数值 |
| F4 | **同号多明细误判** | 一张发票对应多条明细行是合法的。自动"去重"会删掉真实业务数据 | 结果直接给"已删除 N 行"而不是"待复核清单" |
| F5 | **只报重复不报位置** | "有 18 个重复"没法交差，必须说出在哪个文件/哪张表/第几行 | 结果没有来源四件套 |

> 一句话：**"0 条结果"和"根本没读到"必须在输出里长得不一样。**

## 第 1 步：复制这段提示词给 agent

根据是否需要上传脱敏，二选一。

### 版本 A：文件可以直接交给 agent（本地 agent / 可信环境）

```
请对当前目录下所有 .xlsx / .csv 做"按关键列查重"，严格按下面流程，并把每一步结果都写进报告：

1. 先列出你实际读到的【文件清单】，每个文件写：文件名、工作表数、每个工作表读了多少行。一个都不能漏。
2. 关键列是【发票号码】（若没指定，先问我，不要自己猜列）。按【列名】匹配，不是按列号。
3. 关键列一律按【文本】读取：保留前导零；任何纯数字超过 15 位，在报告里单独列为"疑似精度损失"，不要静默当成数字处理。
4. 找出该键值出现 2 次及以上的情况。对每一次出现，记录四件套：来源文件 / 工作表名 / 原始行号 / 单元格地址。
5. 区分两种语义：【键完全重复】和【同键多行（可能是同一发票的多条明细）】。只输出"待复核清单"，绝对不要自动删除或合并任何行。
6. 输出一个新的 .xlsx，包含 4 个 sheet：①结论 ②待复核清单 ③跳过与异常 ④已读清单。
   结论里必须有这一句模板：「重复键 N 个 · 已读 X 文件 / Y 表 / Z 行 · 状态：完整/不完整」。
7. 如果任何文件/工作表没读到，明确写在"跳过与异常"里，并把状态标为"不完整"。不要只说"处理完成"。
8. 不要修改任何原文件，结果另存为新文件。

完成后，把你实际生成的报告内容贴给我看，不要只说"已完成"。
```

### 版本 B：数据敏感，不能上传原文

```
我要查一批敏感表格的重复，不能上传原文。请按这个流程：

1. 我先只提供【列名清单】和【合成样例】（假数据，格式和真实一致）。你据此给我一段能在【我本机】运行的脚本或明确的 Excel/WPS 操作步骤。
2. 脚本/步骤必须满足：只读原文件、结果另存新文件、关键列按文本、保留前导零、超 15 位数字报警、列出每个文件的每个工作表读了多少行、重复项给出来源四件套、不自动删除任何行。
3. 脚本里必须有显式的"已读清单"输出；如果某个 sheet 没读到，要能明确看出来，而不是报告 0 条重复。
4. 给我 3 个反例数据的预期结果，让我先验证脚本是对的，再拿真实数据跑。

不要让我上传真实文件。
```

版本 A 省事，版本 B 安全。财务、HR、涉密数据一律用 B。

## 第 2 步：结果回来后，按这张清单逐条核对

不要因为 agent 说"完成"就信。花 60 秒过一遍：

- [ ] **已读清单在不在？** 有没有写明读了几个文件、几张表、多少行。没有 = 不可信，退回重做。
- [ ] **0 条重复时，有没有同时给出已读数？** 只有"没发现重复"= 不可信。
- [ ] **状态是"完整"还是"不完整"？** 有跳过的文件/表却标"完整"= 不可信。
- [ ] **键列是文本吗？** 前导零还在吗？20 位号码有没有精度告警？
- [ ] **有没有"待复核"而不是"已删除"？** 出现自动删行/合并 = 立即停止用这份结果。
- [ ] **每条重复有没有来源四件套？** 文件 / 表 / 行号 / 单元格，缺一不可。
- [ ] **抽 3 条回源文件里人工核对。** 定位不上 = 整份结果作废。

任何一条打叉，让 agent 重做，不要将就用。

---

## 第 3 步：先用反例测它，再给真实数据

在相信 agent 之前，先丢一份"陷阱表"测它。把下面三个反例做成文件（或一个 sheet），看它的输出对不对。

| 反例 | 构造 | 正确答案 | agent 答错说明 |
| --- | --- | --- | --- |
| **藏在第二个 sheet** | 文件1 的 Sheet1 有一个号 `A100`，Sheet2 也有 `A100` | 应报 1 组重复，且来源写到 Sheet2 | 只读了 ActiveSheet（F1） |
| **长号只差末位** | `12345678901234567890` 和 `12345678901234567891` | 两个文本应判为**不同**；若被读成数值则报警 | 精度被吞（F2） |
| **同号多明细** | 发票 `F001` 有两条不同金额明细 | 应进"待复核"，**不能**判为可删除重复 | 误删业务数据（F4） |

三个都答对，再拿真实数据跑。答错任意一个，说明需要更强的提示词或本地脚本（切到版本 B）。

更多反例和判定细节见 `references/failure-cases.md`。

## 输出规范（让结果能交差）

一份合格的查重结果是一个 `.xlsx`，固定 4 个 sheet，长格式，不做花哨样式：

| Sheet | 关键列 | 作用 |
| --- | --- | --- |
| 结论 | 重复键数 / 已读文件数 / 已读表数 / 已读行数 / 状态 | 一句话自证"我到底做了什么" |
| 待复核 | 键值 / 判定类型 / 出现次数 / 四件套位置 / 行内容摘要 | 交审计、人工核对的主表 |
| 跳过与异常 | 文件 / 表 / 异常类型 / 原文 / 建议 | 精度损失、没读到的表都在这里 |
| 已读清单 | 文件 / 表 / 行数 / 键列 / 是否参与 | 防"静默漏检"的底账 |

规则：结果另存新文件；不覆盖原件；CSV 输出带 BOM 或可指定编码；每行带来源，不合并单元格。

---

## 边界：这个技能不做什么

- 不做网页查重工具，不写前端页面——那是被 agent 替掉的东西
- 不做 OCR、不做 PDF 转表格——那是另一个问题
- 不做两版 Excel 的单元格差异比对——只做"按关键列查重"
- 不做自动去重、自动清洗——只出待复核清单
- 不做公式重算、不比对样式/批注/条件格式
- 不假装支持老式 `.xls` 二进制（先让用户另存为 `.xlsx`）

---

## 完成后怎么收尾

给用户的最终交付只有三样：

1. 一段他可以直接复制的提示词（版本 A 或 B）；
2. 一份 60 秒校验清单（第 2 步）；
3. 三个反例（第 3 步），让他先测再信。

不要承诺"agent 一定查得对"。承诺的是：**照这个做，agent 出错时你能在交差之前发现。**
