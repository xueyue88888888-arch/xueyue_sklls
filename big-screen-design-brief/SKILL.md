# 大屏设计任务书（参考图 → 元素分类 → HTML）

> **模型要求**：本技能的输入是一张参考图。执行它的模型必须**多模态**——能看图，
> 并能读出图里的文字（OCR）和配色、间距。纯文本模型会照着描述编布局、编文案，
> 产出看着完整但和原图对不上；这类任务不要派给纯文本模型。



## 谁用、解决什么

**设计师拿着一张参考图**（竞品截图、mood board、自己画的效果图）说"我要做成这样"。
但一张大屏里混着四种完全不同的东西，**必须分开处理**，否则要么写不出来，要么写出来切不了图：

- 纯色块 / 渐变 / 描边 / 切角 / 发光 → **CSS**，一个 div 就行
- 图标 / 装饰线条 / LOGO / 书法字 → **SVG 或切图**
- 牧场实景 / 工厂航拍 / 产品摆拍 / 门店夜景 → **AI 生成图片**（或实拍素材）
- 地图 / 折线 / 柱状 / 环形 / 仪表盘 → **数据图表**（ECharts）

新手最常犯的错：把"照片感"的东西交给 CSS 硬拼（丑且糊），或者把"纯色卡片底"也去 AI 出图（浪费且不可复用）。

> 核心动作只有一个：**先分类，再开工**。分对了，剩下都是体力活；分错了，整块返工。

```
参考图 → 拆解 → 四分类(A/B/C/D) → 任务书 → Agent 写 HTML → html-screen-to-design-source 切图
          ↑ 本技能                                          ↑ 下游技能
```

## 第 0 步：先判断两件事（30 秒，决定整条路线）

### 0.1 用户的目标工具是什么？

**如果对方说的是帆软 / FVS / FineVis / 数据可视化大屏工具**，先明确告诉他这句话：

> **建议先做 HTML，再转 SVG 设计源，最后交给帆软开发。**
> 原因：通用 agent 写 HTML 的能力最强、HTML 能被浏览器真实渲染和逐像素验收、
> 而 HTML → SVG → 蓝湖标注 → 帆软开发这条链路已经有成熟流水线。
> 直接在帆软里靠描述拼大屏，等于放弃了 agent 最擅长的部分。

分工要讲清楚（避免对方以为要交付一个能跑的帆软文件）：

| 环节 | 谁做 | 产出 |
| --- | --- | --- |
| 设计 | agent 写 HTML | `index.html`（固定画布、静态模式）|
| 切图/标注 | `html-screen-to-design-source` | SVG 设计源 + 全套切图 PNG |
| 上传评审 | 蓝湖 / Figma | 可点选、可标注的稿件 |
| 开发 | 帆软 / FVS 开发 | 按标注还原布局；**图表用 FVS 原生组件重建**，不搬图片 |

最后一行很关键：设计源里的图表是**占位**，只用来定位置和尺寸，真数据由开发接。

### 0.2 用户给你的输入是什么形式？

三种都支持，但流程不同：

| 输入 | 你要先做什么 | 容易踩的坑 |
| --- | --- | --- |
| **只有参考图** | 网格拆解 → 四分类 → **反向补参数**（图里没有的数据、真实尺寸、品牌色值都要问） | 照抄视觉但不知道数据口径；图里文字看不清就自己编 |
| **只有文字需求** | 先用文字画出模块网格（谁在左、谁在右、各几列）→ 再定视觉规范 → 再造一个"参考图"（可用 AI 生成概念图）| 一上来就问"配色和字体"，其实连模块都没定 |
| **图文结合**（最常见）| 图当骨架、文字当约束：图定布局与视觉，文字定数据、品牌、口径 | 图与文字冲突时以**文字**为准（数据不能编） |

缺什么就问什么，但**一次问完**（画布尺寸 / 模块划分 / 真实数据 / 品牌原件 / 目标工具），
不要来回挤牙膏。能自己定的先定下并注明"这是我替你定的，可改"。

## 第 1 步：把参考图拆成元素清单（别一上来就写代码）

**网格扫描法**：把参考图按 8×6 网格切开，逐格回答两问 ——「这格画的是什么？」「它有没有可能用 CSS 画？」

产出这样一张表（每行一个元素，不要合并）：

| 编号 | 位置（网格） | 元素 | 内容 | 分类 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 01 | A1–A8 | 顶部通栏背景 | 夜色实景 + 城市天际线 | C | AI 或实拍，2752×200 |
| 02 | A1 | 品牌 LOGO | 官方矢量 | B | 必须用官方原件，不许 AI |
| 03 | A4 | 主标题 | 「XX 全产业链数智化指挥中心」 | A | 真文本 + 描边/光晕 |
| 04 | A3–A6 | 标题装饰条 | 折线 + 光点 + 两端金色 | B | 内联 SVG，端点坐标要准 |
| 05 | A7 | 书法标语 | 「让一切更美好」 | B | 书法 = 矢量/位图切图，AI 重绘会失真 |
| 06 | B2 | 顶部指标卡 ×3 | 底框 + 图标 + 数值 | A + B | 底框 CSS，图标独立 |
| ... | | | | | |

**判定小抄**

- 出现**光照、材质、反射、景深、真实纹理** → 一定是 C（AI/实拍），CSS 做不出来
- 形状**由数据决定**（地图轮廓内的点位、折线高低） → D
- 边缘**锐利、纯色、可参数化**（圆角、切角、渐变、1px 线） → A
- 是**单色线条图形**（图标、箭头、装饰折线） → B

细分类决策树见 `references/asset-classification.md`。

## 第 2 步：四分类的落地方式

| 类 | 类型 | 落地 | 交付形态 | 例 |
| --- | --- | --- | --- | --- |
| **A** | CSS/DOM | `div` + 渐变/描边/切角/阴影 | 代码，无图 | 卡片底、指标条、分隔线、标签、按钮 |
| **B** | 矢量 | 内联 `<svg>` 或独立 SVG/PNG | 每件一个文件 | 图标、装饰条、LOGO、书法、地图轮廓 |
| **C** | AI 位图 | 用 `image-gen` 技能生成 → `assets/` | 每张一个 PNG | 牧场、工厂、卡车、产品摆拍、门店夜景 |
| **D** | 数据图形 | ECharts / canvas | 运行时渲染 | 地图、折线、柱状、环形、仪表盘 |

**永远不要用 AI 生成的**：数据、文字、图标、LOGO、卡片底框。
**最好不要用 CSS 硬做的**：照片级场景、产品摆拍、有透视的实景。

## 第 3.5 步：视觉质量（决定好不好看）

**先看骨架再补皮肤**：参考图缩到 25% 并去色，先复刻"几块、谁大谁小、留白在哪"，再补描边/发光/图标。
倒过来（先堆特效）一定返工。

七条硬数字（详细清单见 `references/visual-quality.md`）：

| 维度 | 规则 |
| --- | --- |
| 焦点 | 一屏只有一个；焦点区外发光 ≤ 1px 描边 + 6px 柔光 |
| 深度 | 页面底 → 模块底 → 卡片底，相邻亮度差 3–6；靠明度分层，不靠大阴影 |
| 发光 | 只允许 3 类（主标题 / 关键数值 / 主视觉）；禁大面积光斑；金色+描边+发光不许叠在一个数上 |
| 字号 | 一屏 ≤ 6 种，步进 ≤ ×1.25；数值 ≥ 标签 1.6×，单位 ≈ 数值 0.5×；数字 `tabular-nums` |
| 间距 | 模块间距 = 卡片间距 × 2；卡内 padding 统一 12–16；标题→内容距离 > 内容→内容 |
| 色彩 | 主色 + 强调色 + 语义色，色相 ≤ 4，强调色面积 ≤ 10%；正文对比 ≥ 4.5:1 |
| 动效 | 全屏 ≤ 3 处，周期 2–4s；关掉动效信息仍完整 |

交付前用末尾那张 10 项自评表打分（每项 0–2，≥16）——但自评只是辅助，
**真正的交付硬线是第 3.6 步的客观还原校验**：截图与参考图配准后的得分不达标，自评再高也不交。

## 第 3.6 步：客观还原校验（有参考图时必做，硬性门槛）

有参考图的任务，HTML 写完必须先渲染截图，再跟参考图做配准对比。**不许靠"看起来像"或自评打分判断还原度**——
主观自评正是漏掉布局偏差的元凶（深蓝科技风两张图乍看很像，实测结构差 60%）。

```bash
python scripts/verify_reference_match.py \
  --reference <参考图路径> --render <HTML截图路径> \
  --out <报告.json> --threshold 0.70
```

- 脚本独立处理尺寸/比例差异，统一缩放后算灰度 SSIM + 边缘 SSIM 的综合分；
- 同时输出 9 个分区得分和最差 3 区，直接指出哪块画歪了；
- **得分 < 0.70 就退回改布局，改完重测**，直到达标才进入下游切图。

迭代顺序：先看最差 3 区 → 回参考图按 8×6 网格核对该区元素的 x/y/w/h 和样式 → 改 CSS → 重渲染 → 重测。
边缘分偏低通常是布局/轮廓错位（模块位置、大小、仪表盘/环图形状），灰度分偏低通常是明暗或配色。

## 第 3.7 步：端到端 FVS 还原校验（目标 ≥0.90，硬门槛）

第 3.6 步校验的是「HTML 还原稿 vs 参考图」。真正交付给用户的是 FVS，所以还要校验「帆软实机渲染 vs 参考图」，目标 **≥0.90**。

实测基线（2026-11-24，帆软 8075 实机 + 9 分区 SSIM）：
- **纯切图 + text 文字模式：0.927**（文字/数字全可编辑，图表切图）——这是保底可达的标准
- 原生图表 + 自动擦除底图：0.918（3 图）~0.851（6 图样式未调），图表可编辑但依赖上游 SVG 质量
- 旧默认 table 模式只有 0.871（KPI 大字被折叠进表格塌成 0/5）——**文字承载必须用 text 模式**

做法：
1. `node tools/svg-to-fvs.cjs <svg> <名字> 1920 1080`（默认已是 text 模式）
2. FVS 拷进帆软 reportlets 目录，`node tools/fvs-shot-named.cjs <viewlet> <png>` 实机截图
3. `verify_reference_match.py --reference <参考图> --render <实机截图> --threshold 0.90`
4. 得分 < 0.90 看最差 3 区：若是帆软未注册水印挡住的区域，可用遮罩复算；若是真布局/字体差，回 HTML 改

**注意**：帆软未注册版会在右下角盖一块水印，会拉低该区分 0.10+。这是授权问题不是转换 bug，扣水印后真实差异通常 <3%。

## 第 4 步：任务书（复制改括号）

```
【任务】照参考图做一块 XX 数据大屏，输出可运行的单页 HTML。
参考图：<路径或附件>；业务：XX；画布：2752×1204。

一、画布与层叠
- 固定画布，transform: scale() 适配；不做响应式断点
- 层叠：页面底 → 模块底 → 卡片底 → 照片/图表 → 图标 → 文字

二、结构（按参考图对应）
- 页头：底图 + LOGO + 主标题 + 副标题 + 书法标语 + 3 个顶部指标卡
- 左列上：<模块> 标题 + 实景图 + 4 指标条 + 1 图表 + 1 仪表盘
- 中间：地图 + 4 KPI + 3 浮层卡（预测 / 选址 / 实时动态）
- 右列上/下：<模块> 指标 + 图表

三、数据（占位，固定种子，刷新不变）
- <模块>：<指标 1> 4 座 / <指标 2> 31,882 头 / …
- 图表各 7 个数据点

四、视觉规范
- 底色 #020A18；卡片渐变 #041A38→#062A4F；描边 rgba(47,155,214,.25)
- 主文字 #EDF8FF；次要 #9ECBE3；强调金 #F2E9B8；增长 #49E38C
- 字体 SimHei / Noto Sans SC（自由字体）
- 切角 ≤10px；发光克制（1px 描边 + 6–10px 柔光），禁止大面积光斑
- 字号阶梯（≤6 种）：主标题 42–46 / 模块标题 26–28 / 关键数值 26–28 / 卡片标题 15.5 / 正文 12–13.5 / 单位 9–10.5
- 三层明度：页面底 → 模块底 → 卡片底，相邻亮度差 3–6；卡片用 1px 半透明描边 + 极轻内发光分层
- 强调色（金）只给关键数值与语义，面积 ≤10%；图表系列色取主色系 3–5 档，不用彩虹

五、图片素材（分类见下表，**C 类由 AI 生成，先给占位**）
| 编号 | 元素 | 类别 | 尺寸 | 生成/提供方式 |
| 01 | 顶部通栏实景 | C | 2752×200 | AI：夜色天际线 |
| 07 | 牧场航拍 | C | 717×285 | AI：高原牧场 |
| 13 | 产品摆拍 | C | 707×252 | AI：乳品陈列 |
| 02 | LOGO / 书法 | B | — | 官方原件，不许重绘 |

六、工程要求（决定后面能不能切图）
见下节「7 条硬约束」和紧随其后的「命名契约（双写）」，一条都不能省。

六·补、命名契约（双写，必须写进 HTML）
每个可视块同时写 data-el 和 data-name（也可以只用 data-name，由脚本自动推导 data-el），按下表选词：
| 设计元素 | data-el | data-name 前缀 |
| 页面/面板底 | page-bg / panelbg__* | page-bg__ |
| 标题栏 | titlebar | panel-header__（标题文字）；栏底用 title-bar-bg__ |
| KPI 卡 | card__kpi | panel-header__（KPI文字）或 title-bar-bg__（卡底） |
| 筛选框 | filter / filter-item | filter-bar__ / filter-bar-bg__ |
| 查询按钮 | query / btn-query | filter-bar__（含"查询"文字） |
| 表格 | table | table-header__ / table-rows__ / table-bg__ |
| 图表容器 | chart / chart__<type> | chartref__（容器内内嵌 data-chart-option，见下「图表可编辑三条件」） |
重复件加 -2 -3 或 __序号；同一节点上两个属性语义必须一致。
为什么：下游 svg2fvs 只读 data-name 的 8 类白名单前缀（page-bg / title-bar-bg / filter-bar-bg / table-bg / panel-header / filter-bar / table-header / table-rows）；只写 data-el 它看不到，只能靠几何猜，命中率下降。

### 图表可编辑三条件（想"图表能改数据"必做，否则只能切图）
1. **图表容器坐标必须对**：用 flex/grid 正常文档流，不要写死 `position:absolute; left:10px; top:36px`（父容器一塌，getBoundingClientRect 会给出错坐标，图表全堆左上角）。
2. **图表数据必须内嵌**：容器上加 `data-chart-option="<base64(ECharts option)>"`，option 要带完整样式（颜色、渐变、min/max、legend、splitLine），否则原生图表能用但跟原图不像。用 `inject_chart_options.py` 注入。
3. **page-bg 不能烘煊图表形状**：底图只能有背景/面板/装饰，图表区要留空；如果底图已把图表画进去了，svg2fvs 会自动擦除图表区(eraseRects)但样式可能需要重调。

如果上游做不到 2（图表是 CSS/SVG 手绘而非真 ECharts），那就只能切图（图表不可编辑）。想全可编辑，图表必须用真 ECharts。

七、交付
index.html + css/ + js/ + assets/；附 2752×1204 整页预览 PNG
```

## 第 5 步：AI 图怎么出（C 类专用）

先给**占位图**把布局定死，再逐张生成替换 —— 顺序反了会反复改布局。

```bash
# 用 image-gen 技能出图；尺寸按设计稿 1:1 或 2x
alma image generate "<prompt>" --size 1408x560
```

**Prompt 公式**：`主体 + 场景 + 光线 + 镜头/景深 + 色调 + 用途约束`

> 清晨高原牧场航拍，绿色草场与黑白花奶牛成排，侧逆光柔和，35mm 宽幅俯拍，
> 冷蓝绿色调与深蓝夜色统一，画面右侧留空给数据卡，无文字无水印

6 条硬规则（不遵守就会出现"五张图风格不一致"）：

1. **一套风格词贯穿全部图**（光源方向、色温、材质、镜头），不要每张重新描述
2. **尺寸写死**，与设计稿显示尺寸一致（或 2 倍），不要生成后再乱缩放
3. **负面词固定**：`text, letters, numbers, watermark, UI, screenshot, logo, border, frame`
4. **要为深色底服务**：深色场景或可抠像的纯净背景；需要透明时出纯色背景后期抠
5. **每张写明用途**（"模块顶部通栏 717×285，上沿留出标题空间"），别只说"来张牧场"
6. **生成后统一压暗降饱和**：`filter: brightness(.9) saturate(1.02)`，照片不许抢过数据

Prompt 模板库、一致性与抠图清单见 `references/ai-image-prompts.md`。

## 第 6 步：7 条硬约束（写进任务书，决定能不能切图）

| # | 约束 | 不这么做会怎样 |
| --- | --- | --- |
| 1 | 文字必须是真文本，不许画进背景图 | 切图后改不了一个字，也标不了规格 |
| 2 | 卡底 / 图标 / 照片 / 文字分层 | 糊成一张，谁也没法单独下载或替换 |
| 3 | 图标是独立节点，不用字体图标 | 字体图标既是字体又切不出图 |
| 4 | 禁用渐变文字、`backdrop-filter`、`mask`、复杂 `filter` | Figma 导入后：文字变黑、磨砂变实心、图层消失 |
| 5 | 固定画布 + 静态模式开关（`?live=1`） | 每次渲染都不同，量不了坐标、验收不了 |
| 6 | 元件稳定命名 `data-el="card__kpi"`，重复件加序号 | 切图只能靠"第几个 div"，一改就错位 |
| 7 | 占位数据固定种子，时间类文字写死 | 不可复现 = 不可验收 |

补充两条：

- 照片素材**保留原始 PNG**，不在 HTML 里压成 JPG（后面要转 RGBA PNG 交付，JPG 会带白底）
- 卡片发光用「1px 描边 + 极轻阴影」表达；大面积 `radial-gradient` 光斑切图后会变成多余色块

## 第 7 步：验收

设计侧：
- [ ] **客观还原校验通过**：`verify_reference_match.py` 得分 ≥ 0.70（有参考图时；不达标不算完成）
- [ ] 单屏不滚动，缩放不变形
- [ ] 模块层次清楚：标题区 / 指标区 / 图表区不打架
- [ ] 数值和单位字号不同级；同类卡片间距、字号、颜色完全一致
- [ ] 缩到 30% 还能看清结构；发光不糊

设计质量自评（每项 0–2 分，≥16）——辅助参考，不能替代上面的客观校验：
单一焦点 / 三层明度 / 发光纪律 / 字号阶梯 / 间距节奏 / 色彩克制 / 图表统一 / 照片不抢戏 / 动效克制 / 缩略可读。

工程侧（决定能不能切图）：
- [ ] 每块文字都是 DOM 文本（选中能复制）
- [ ] 每个图标是独立节点
- [ ] 卡片底与内容分层（隐藏文字后只剩底框）
- [ ] 无 `background-clip:text` / `backdrop-filter` / `mask`
- [ ] 有静态模式，连渲染两次截图一致
- [ ] 元件都有 `data-el` 命名
- [ ] 每个可视块同时有 `data-name`（白名单前缀见第 4 步「命名契约（双写）」）

## 第 8 步：怎么"改"（迭代话术)

用**定位 + 现象 + 期望**三句，比"这里不好看"有效十倍：

> 「销售端」的 4 个 KPI 卡：数字和"万元"贴太近，数字 26px、单位 12.5px，中间留 4px；卡片高度 80 → 84。
>
> 页头三个指标卡之间的分隔线看不见，应该是 1px 竖向渐变线 + 6px 柔光。
>
> 地图区域偏小，底图裁到 751×446，标注文字 9px。

反例：「整体再高级一点」——会得到随机结果。

## 第 9 步：交给下游（交付契约）

`html-screen-to-design-source` 只认这几个东西。任务书里必须写死，否则下游要返工：

| # | 交付项 | 具体要求 |
