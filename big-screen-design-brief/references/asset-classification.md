# 素材分类决策树

一张大屏上的每个元素，落到四类之一：**A CSS / B 矢量 / C AI 位图 / D 数据图形**。
分类错了，返工代价最大 —— 用 CSS 硬凑照片会糊，用 AI 生成卡片底会不可复用。

---

## 一句话判据

| 看到什么 | 分类 |
| --- | --- |
| 有光照方向、材质反射、景深虚化、真实纹理 | **C** |
| 形状随数据变化（折线高低、地图点位、环形占比） | **D** |
| 单色线条/面，边缘锐利，可参数化（圆角、切角、1px 线、渐变） | **A** |
| 单色线条图形（图标、箭头、装饰折线、LOGO、书法） | **B** |

---

## 决策树

```
这个元素的形状会随数据变化吗？
├─ 会 ────────────────────────────────→ D 数据图形（ECharts/canvas）
└─ 不会
    └─ 需要"照片级真实感"（光/材质/景深/纹理）吗？
        ├─ 需要 ────────────────────────→ C AI 生成（或实拍素材）
        └─ 不需要
            └─ 是可以拆成"纯色块 + 边框 + 阴影"的矩形/多边形吗？
                ├─ 可以 ────────────────→ A CSS/DOM
                └─ 不可以（异形曲线、精细线稿、文字造型）→ B 矢量
```

## 容易被分错的 8 个边界情况

| 元素 | 直觉分类 | 正确分类 | 原因 |
| --- | --- | --- | --- |
| 卡片外发光 | C（截图抠） | **A** | 1px 描边 + `box-shadow` 就能表达；截图会带背景色 |
| 磨砂玻璃卡（backdrop blur） | A | **A（但要降级）** | `backdrop-filter` 设计工具不认，改用半透明底色 + 细描边 |
| 标题装饰折线 | A | **B** | 折线是异形，SVG 一行 path；用 CSS 拼 div 后期改不动 |
| 书法标语「让一切更美好」 | C | **B** | 书法是造型艺术，AI 重绘会丢字形；必须矢量或位图切图 |
| 品牌 LOGO | C（重画一个） | **B** | 必须用官方原件，AI 生成的 LOGO 属于品牌事故 |
| 地图轮廓 | C（生成一张地图图） | **D（或 B）** | 轮廓用 ECharts geo 或 SVG；点位与流向必须由数据驱动 |
| 产品摆拍（瓶+杯+水果） | A（拼 div） | **C** | 有反射和投影，CSS 做不出可信效果 |
| 仪表盘/环形进度 | C（画一张） | **D** | 数值会变，必须运行时渲染 |

## 工作量估算（按分类数个数就行）

| 分类 | 单个耗时 | 说明 |
| --- | --- | --- |
| A | 5–15 分钟 | 一顿 CSS 的事；同类卡片抽成组件 |
| B | 15–40 分钟 | 要调坐标；图标可批量导出 |
| C | 20–60 分钟/张 | 含生成、挑选、压暗、替换占位 |
| D | 30–90 分钟 | 图表样式与数据绑定；地图最费时 |

一张典型 6 模块大屏的分布（来自实际项目）：
**A 约 60 处、B 约 35 处、C 约 7 张、D 约 11 个**。
C 类数量少但最容易拖工期 —— 先做占位、尽早排生成队列。

## 实战示例：某乳品企业全产业链指挥中心（2752×1204）

| 区域 | 元素 | 分类 | 备注 |
| --- | --- | --- | --- |
| 页头 | 长条底图（夜色天际线） | C | 2752×200，底部渐隐融进数据带 |
| 页头 | 官方 LOGO | B | 官方透明底原件 |
| 页头 | 主标题 + 副标题 | A | 真文本；标题渐变+光晕要烘成实色+滤镜 |
| 页头 | 标题装饰条（折线+光点+金端） | B | 内联 SVG，端点 1px 对齐 |
| 页头 | 书法标语 | B | 矢量/位图切图，禁用 AI 重绘 |
| 页头 | 3 个顶部指标卡（底+图标+数值） | A + B | 卡底 CSS；图标独立 |
| 牧业 | 牧场实景 | C | 717×285，压暗降饱和 |
| 牧业 | 指标条 4 联 | A + B | 条底一张图；图标各自一张 |
| 牧业 | 近 7 日产量折线 + 优质乳率仪表 | D | ECharts |
| 工厂 | 工厂航拍 | C | 714×276，亮度 ×0.9 |
| 工厂 | 4 指标 + 柱状 + OEE 仪表 | A/B/D | |
| 销售端 | 全国地图（底图/流向/点位三层） | D + B | 底图矢量化，流向与点位数据驱动 |
| 销售端 | 4 个 KPI 卡（六边形图标） | A + B | 六边形图标切图 |
| 销售端 | AI 预测 / 选址 两张玻璃卡 | A | 半透明底 + 细描边，不用 backdrop-filter |
| 销售端 | 实时消费动态（滚动列表） | A | 真文本，时间列固定 |
| 销售端 | 门店实景通栏 | C | 1236×552，四边渐隐 |
| 物流 | 卡车 + 城市实景 | C | 719×245 |
| 物流 | 配送网络小地图 | D/B | 155×116，含羽化边 |
| 电商 | 产品摆拍（乳品陈列） | C | 715×252，右侧/下沿渐隐 |
| 电商 | 渠道占比环形 + TOP5 + 趋势 | D | |
| 全局 | 页面底色、模块底、分隔、扫描线 | A | 纯 CSS/一张底图 |

结论：**这张屏真正需要 AI 出图的只有 7 张**（天际线、牧场、工厂、卡车、门店、产品、地图底）。
其余 90% 是 CSS 与矢量 —— 这也解释了为什么"先分类"能省掉大半返工。
