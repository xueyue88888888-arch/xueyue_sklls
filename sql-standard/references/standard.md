# SQL 编写规范

七章，每条一句话说明为什么。写 SQL 前扫一遍，评审时逐条对。

## 一、结构

1. **必须分四段**：参数 → 口径/范围 → 事实 → 结果。每段一个 CTE，起名字。
   为什么：一段式子查询没人能评审，改一处要看全篇。
2. **子查询嵌套不超过 2 层**，第 3 层就提成 CTE。
3. **每个 CTE 只干一件事**：过滤、聚合、关联、排序分开写。
4. **结果集最后再排序**，中间层不 ORDER BY。
5. CTE 名用动词短语或名词短语：`emp_active`、`cert_latest`、`result`。

## 二、命名

6. 表别名 3-8 字符有意义：`emp`、`cert`、`plan`。禁止 `a/b/c/t1`。
7. **同一实体全程同名**：人员就叫 emp，别一会儿 e 一会儿 s。
8. 派生列必须表达业务含义：`abnormal_cnt`，不是 `cnt1`。
9. 布尔/标记列用 `is_` 前缀：`is_active`、`is_bk`。
10. 日期列带 `_dt` 后缀，时间戳带 `_time`，金额带 `_amt`。

## 三、可读

11. 关键字**大写**，标识符小写 + 下划线，全篇一致。
12. 缩进 4 空格，不用 Tab。
13. 单行不超过 120 字符；SELECT 列超过 5 个时一列一行。
14. 列名与 `AS` 对齐不要用空格硬凑，靠工具格式化。
15. 注释说明「为什么这么写」，不复述「这里在做什么」。
16. 复杂条件拆成有名字的布尔列，不要写一长串 `AND`。

## 四、正确（最要紧的一章）

17. **除法**：分母一律 `NULLIF(x, 0)`，比例再 `ROUND(..., 2)`。
18. **NULL**：判断用 `IS NULL`；聚合用 `COALESCE`；`NOT IN` 换 `NOT EXISTS`。
19. **时间切片**：历史表（含 `begda`/`endda`）必须三段齐全
    `begda <= 当日 AND endda >= 当日 AND aedtm <= 当日`。
    为什么：只写其中两段，会取到未生效或未来才录入的记录。
20. **取最新一条**：`ROW_NUMBER() OVER (PARTITION BY 键 ORDER BY 时间 DESC, 序号 DESC)`，
    外层 `WHERE rn = 1`；排序键**至少两个**。
21. **JOIN 必须说清基数**：1:1 还是 1:N。1:N 要么先聚合，要么接受翻倍并在注释里写明。
22. **不要用 DISTINCT 掩盖重复**：先找重复的成因（JOIN 放大 / 历史切片），再用 ROW_NUMBER 精确去重。
23. **去重必须写明按什么键**：`按工号+日期`，写在注释里。
24. **哨兵值集中定义**：`'__ALL__'`、`'__UNMAPPED__'` 这类在 CTE 里定义一次，别散落在条件里。
25. **字面量纯净**：字符串里不许有全角标点、零宽字符、弯引号。
    为什么：看起来一模一样的值，匹配永远不中，而且不报错。
26. **隐式类型转换要显式化**：工号/编码类字段与数字比较时 `CAST` 或加引号，确认前导零不丢。

## 五、性能

27. 数仓表必须带分区/日期条件。
28. 只取需要的列，不用 `SELECT *`。
29. 分区字段上不套函数。
30. 多表关联前先缩小结果集（把过滤放在 CTE 里，不要全表 JOIN 完再过滤）。
31. 明细类查询必须有 `LIMIT`。

## 附：评审时只问三个问题

1. 口径说得清吗？（粒度、范围、边界）
2. 数字对得上吗？（总数 = 分组和；KPI = 明细行数）
3. 明年还能改吗？（没有写死的日期、清单、魔法值）
